# 结构化召回 0.2 设计

## 目标

在不改变“Markdown 是唯一事实源、默认不联网、旧库无需迁移”的前提下，为共享记忆增加可追溯元数据、可解释召回、上下文预算和健康统计。SQLite、Embedding、自动 LLM 抽取、PageRank 与宿主级自动注入不属于本版本。

## 存储格式

新建候选记忆时，在 Markdown 正文前写入兼容 YAML 的 JSON 标量前置元数据。字段包括稳定 ID、类型、来源任务、来源代理、创建时间、置信度、标签和关系。旧文件没有前置元数据时继续按普通 Markdown 读取，不自动改写。

支持的记忆类型为 `note`、`fact`、`decision`、`event`、`skill`、`task`、`preference`；置信度为 `unspecified`、`tentative`、`inferred`、`confirmed`；关系为 `related_to`、`requires`、`solved_by`、`uses`、`patches`、`conflicts_with`。关系只建立显式链接，本版本不做图排序。

## 召回与上下文

召回继续使用确定性本地词项评分，同时区分标题、正文、路径、标签和元数据命中。每条结果返回分数、命中原因、记忆 ID、类型、来源任务、来源代理、创建时间与置信度。调用方可用最低分过滤低相关结果。

`context` 在现有字符上限之外增加近似 Token 预算，两者同时提供时取更严格的限制。输出按完整区块逐条装配，优先保留安全声明和核心记忆，再加入高分召回结果。历史内容始终标记为不可信参考，当前用户指令、系统约束和当前仓库事实优先。

## 统计与兼容性

新增 `stats` 命令，报告记录数量、集合分布、类型分布、关系数量、元数据覆盖率和活动/归档任务数量。`doctor` 复用这些统计，并把旧文件缺少元数据、索引可能过期等情况作为警告，不因此判定旧库损坏。

原有 `init`、`status`、`remember`、`recall`、`context`、`archive`、`reindex` 和 `doctor` 参数保持兼容。新增参数均为可选项，现有脚本无需修改。

## 验证

测试通过公开的 `MemoryHub` 和 CLI 接口覆盖：新记忆元数据、旧文件召回、召回理由与最低分、上下文安全声明与预算、统计结果、JSON 输出以及现有并发和归档行为。每项行为按单测试红灯、最小实现绿灯的顺序完成。
